# ADR-013: Dual-Mode Behavioral Macro Stubs & Zero-Failure Editor Architecture

## 1. Context & Incident
When synthesizing and simulating ASIC designs containing hard macros (e.g. OpenRAM SRAMs like `sky130_sram_1kbyte_1rw1r_32x256_8`), two critical architectural defects were discovered:

1. **Hollow Macro Stubs Breaking Simulation**:
   The Macro IP Catalog ("Shopping Cart", `core/pdkmanagers/macro/ipcatalog.py`) previously parsed macro LEF files and generated empty module stubs (`// Black-box stub auto-generated by Silis Shopping Cart`). When placed in `rtl/`, the Verilator simulation runner compiled the hollow stub instead of the actual functional memory model. Testbenches accessing memory arrays (e.g. `dut.u_sram.mem[0]`) failed with fatal errors:
   `%Error: Can't find definition of 'mem' in dotted variable/method: 'dut.u_sram.mem'`

2. **WebEngine/Chromium GPU Pipeline Lockups**:
   On Linux environments without direct GBM (Generic Buffer Manager) hardware buffer support (e.g. standard Ubuntu desktops with Mesa/Nvidia drivers, containerized sessions, or VMs), QtWebEngine emits:
   `GBM is not supported with the current configuration. Fallback to Vulkan rendering in Chromium.`
   If Chromium's GPU compositor stalls, the Monaco JavaScript editor context fails to initialize, leaving the editor surface unresponsive or blank.

---

## 2. Invariants & Decisions Enforced

### Invariant 1: Dual-Mode Behavioral Macro Stubs
Whenever a hard macro is checked out from the Macro IP Catalog, Silis must never emit a hollow, unfunctional module body if a behavioral model is provided by the PDK.
The emitted stub must follow the dual-mode compilation contract:
```verilog
`ifndef SYNTHESIS
// Authoritative PDK Behavioral Simulation Model (Verilator / Icarus / VCS)
// Contains reg [DATA_WIDTH-1:0] mem [0:DEPTH-1];
...
`else
// ASIC Synthesis Black-Box Stub (Yosys / OpenROAD)
module <macro_name> (
    ...
);
endmodule
`endif
```

### Invariant 2: Dynamic Simulation Stub Self-Healing
During `run_simulation()`, `silis.py` must inspect `src_v`. If any file is a hollow synthesis stub lacking internal logic, Silis dynamically queries `libs.ref/<macro>/verilog/<macro>.v` in the active PDK and substitutes the functional simulation model into Verilator's file compilation list.

### Invariant 3: Native QScintilla First-Class Reliability
- QScintilla (`QsciScintilla`) is the official native C++ Qt6 editor backend for Silis. It runs without browser processes, without GPU compositing, without GBM/Vulkan dependencies, and with zero startup latency.
- Monaco (`QWebEngineView`) is supported for web-parity environments, but Chromium flags must use `--disable-gpu-sandbox --log-level=3` to prevent compositor freezing.
- Users can switch instantly between Monaco and QScintilla via the editor backend toggle.
